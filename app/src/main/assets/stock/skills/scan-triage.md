# 巡检结果的含义

`scan_watchlist` 输出一张紧凑表。理解每个字段**能说明什么、不能说明什么**，比记住处理流程更重要。

## 一、四个字段的可靠度不同

| 字段 | 可靠性 | 说明 |
|---|---|---|
| 收盘 / 涨跌幅 | 高（盘中会变） | 由 K 线直接算 |
| 结构方向 | 中 | 由最近高低点递进判断，是描述不是预测 |
| **有信号** | **低** | 近 3 根内 MACD 金叉/死叉，或量能柱连续收缩 |

**"有信号"是最容易被高估的字段。** 它只说明这只票最近发生了指标层面的变化，不涉及位置、不涉及力度、不涉及级别协调。把它当作"值得看一眼"的索引，而不是"机会"的清单。

真正的判断在 `analyze_chan` / `chan-buysell` 里。

## 二、从一批结果里挑值得深入的

一个自然的漏斗，不是必须照做，但能省时间：

**第一步看有没有信号**——没信号的大概率短期内没有新信息，可以先放着。但记住要说明"其余 N 只近期无信号"，否则用户会以为你没看完。

**第二步看方向与信号是否自洽**：

| 方向 | 信号 | 通常意味着 |
|---|---|---|
| 上涨 | 金叉/量能收缩 | 回调可能结束，值得看 |
| 下跌 | 金叉 | 可能是下跌中继的反弹，需要级别确认 |
| 震荡 | 任意 | 中枢内的噪音居多 |

方向和信号不配合时，不必强行解释——直接说"信号与结构不配合"也是一种结论。

**第三步过一遍前提**（见 `when-not-to-trade`）：停牌、一字板、新股、数据量不够的，先排除。

深入几只比较合适？这取决于用户的问题——他问"哪只可以买"，两三只足够给出可操作的答案；他问"把全部看一遍"，那是另一回事，但值得提醒：多只深入会同时消耗上下文和他的注意力。

## 三、汇报时什么值得说

用户要的是结论，不是表格。把中间产物直接贴出去，他会自己去读——而他本来是想让你读。

```
巡检 12 只（日线），2 只值得看，其余 10 只近期无信号。

值得看：
1. 阳光电源(300274) 74.00 +1.23% 结构:上涨
   近 3 根 MACD 金叉，价格在中枢上方，回调没跌回 ZG
2. 恒宝股份(002104) 8.25 -0.60% 结构:下跌
   有信号但方向向下，金叉更可能是下跌中继，建议观察

排除：
  · 中材科技(600176)：连续 3 根一字板，结构无效
  · XX科技：上市 45 个交易日，中枢未形成
```

三件事让这段有用：**说了总数**（让用户知道覆盖面）、**排除了什么**（让用户知道你有判断）、**没信号的那批也提到了**（避免他以为你在挑着说）。

## 四、几个容易产生的误解

- **信号多不代表机会多。** 一批里出现五六个信号是常见现象，它们分布在不同方向、不同位置，不构成"今天机会很多"。
- **巡检是一个时点的快照。** 隔几个小时市场变了，结论要重取，不要拿旧表回答新问题。
- **"有信号"和"该买"之间隔着好几层判断。** 这个差距正是其他 skill 存在的原因。

## 五、什么时候不需要巡检

- 用户只问单只票——`analyze_chan` 更直接
- 自选是空的——工具会返回 `NO_WATCHLIST`，先请用户添加
- 用户要求看全部原始数据——可以照做，但提一句上下文会比较长
