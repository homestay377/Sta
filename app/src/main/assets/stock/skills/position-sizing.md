# 从价位到仓位

给一个价位和给一个可执行建议之间，差的是"买多少"。这份文档提供换算方法和几个约束的由来。

## 一、先看手上有什么

| 需要的 | 拿不到时的处理 |
|---|---|
| 总资金 | 用"总资金的 X%"表述，不换算成具体股数 |
| 单笔风险承受度 | 常见区间 1~2%，可以按这个假设并说明 |
| 止损位 | 没有止损位就无法反推仓位 |

总资金是可以直接问的，也可以不换算——百分比表述对用户同样有用。

## 二、换算关系

```
每股风险 = 入场价 − 止损价
可买股数 = (总资金 × 单笔风险%) ÷ 每股风险
```

A 股一手 100 股，取整时**向下**更稳妥（少买不会改变判断，多买会放大风险）。

一个例子：

```
入场 10.68，止损 10.32 → 每股风险 0.36
资金 10 万，风险 2% → 可亏 2000 元
股数 2000 ÷ 0.36 ≈ 5555 → 5500 股
```

## 三、为什么要设上限

按风险反推有个特点：**止损越近，算出的仓位越大**。止损 0.5% 时可能算出 300% 仓位——数学上"风险 2%"成立，实际上这等于满仓加杠杆。

所以通常还会叠两个约束，取其中最小的：

| 约束 | 常见值 | 作用 |
|---|---|---|
| 单笔风险 | 1~2% | 控制一次错误的影响 |
| 单票仓位 | 15~20% | 防止集中在单只 |
| 单次判断总仓 | 50% 左右 | 防止一次信号赌全部 |

这些数值可以按用户的风格调整，关键是他知道有这几道约束。

## 四、仓位可以跟信号强度挂钩

| 信号 | 通常给的比例 | 逻辑 |
|---|---|---|
| 三买/三卖（中枢外回抽不破） | 接近上限 | 结构最确定 |
| 二买/二卖（低点抬高） | 中等 | 依赖一买成立 |
| 一买/一卖（趋势末端背驰） | 偏小、可分两批 | 反转未确认 |
| 只有背驰、结构未确认 | 先不给仓位 | 判据不全 |

多级别方向一致时可以上调，级别冲突时下调。

## 五、止损位从结构来

| 买点 | 止损依据 |
|---|---|
| 三买 | ZG 下方一点（跌回中枢即判断失效） |
| 二买 | 一买低点（二买的意义就是不破它） |
| 一买 | 一买低点下方一点 |
| 卖点 | 对称处理 |

没有结构位时（比如只有背驰），仓位建议缺一个前提。这时候说"这个位置没有明确的结构止损，仓位只能按你自己能承受的来定"，比硬给一个数字更有用。

## 六、加减仓

| 动作 | 触发 | 幅度 |
|---|---|---|
| 首仓 | 信号成立 | 见第四节 |
| 加仓 | 盈利 + 结构延续 | 每次不超过首仓一半 |
| 减仓 | 结构走坏 | 先减一半，余仓看止损 |
| 清仓 | 收盘破原始止损 | 全部 |

加仓通常只在盈利且结构没坏时进行——摊平成本会让单笔风险失控。

## 七、输出时值得带上的信息

```
操作：
  · 入场 10.68
  · 止损 10.32（ZG 下方 0.3%）
  · 仓位 ≈5500 股（55 手，约 58%）
     按资金 10 万、单笔风险 2% 算；资金不同则股数按比例变，仓位百分比不变
  · 最大亏损 ≈1980 元（2%）
```

把前提写出来，用户能自己校验，也方便他按实际资金调整。

## 八、什么时候不必给仓位

- 用户只问结构、没显露动手意图——给价位就够
- 已经持仓问"要不要卖"——那是减仓问题，`chan-position` 更合适
- 用户没问、上下文也不明确——可以主动问一句"按多大资金算"，比假设更好

每次回答都附一段仓位计算容易显得啰嗦，在用户有动作意图时给更自然。

## 九、几条经验

1. 说了买点却不说买多少，用户要么凭感觉重仓，要么不敢动。
2. 不知道资金就用百分比——比编一个数好。
3. 手数向下取整：少买只是收益低一点，多买是风险变大。
4. 止损近导致的高仓位，需要有上限兜住。
5. 仓位建议带上"如果你资金是 X"的前提，用户能一眼看出是否适用于自己。
